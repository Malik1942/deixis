# Deixis v0.6: a download that works, and a way to hear about the next one

**Scope of this spec:** The site's Download button reaches a dmg; the repo is public; releases are GitHub releases with a download count; the app tells the user once a day when a newer release exists. Tagged `v0.6`.
**Revision:** Sep 14, 2026, after `v0.5`. Decided by Malik the same day: repo public, then an update check.
**Out of scope:** Sparkle or any other update framework, in-app installation of the new build, delta updates, a changelog window, analytics on the site, a check that runs more than once a day.

Read `CLAUDE.md`, then the earlier specs. This spec relaxes the "No network calls" line in `CLAUDE.md` and PRD §3 item 6 for exactly one request, the way R35 relaxed "no gallery": the release check. Every sentence that promised "no network" is rewritten here to say what is true instead; "Nothing leaves the machine" stays where it is about captures and permissions, because it still is.

## 4. Requirements

**R45 Update check.** Once a day, and only then, Deixis asks `https://api.github.com/repos/Malik1942/deixis/releases/latest` for the newest release. The request carries `Accept: application/vnd.github+json` and `User-Agent: Deixis/<version>`; nothing else, no cookies, no cache, an ephemeral session, a 15 s timeout. The reply's `tag_name` (with or without a leading `v`) is compared to `CFBundleShortVersionString` as dotted integers; `1.10` is newer than `1.9`, a pre-release suffix is ignored. A failure of any kind is silent: no alert, no log line above `debug`, the next try is in 24 hours. The first check runs 10 s after `AppState.start()` so it never races the permission alerts or the Help window; `lastUpdateCheck` (R46) prevents a second check within 24 hours across relaunches. The comparison and the decoding are pure functions and get tests; the fetch does not.

**R46 Preferences.** `checksForUpdates: Bool`, default `true`. `lastUpdateCheck: Date?`. `skippedUpdateVersion: String?`. Nothing else is stored about the check.

**R47 Settings › General, "Updates" section.** A switch, "Check for updates", detail: "Once a day, Deixis asks GitHub for the newest release. The request carries the version number and nothing about you or your captures." A `LabeledContent` row "Version 0.6.0" with a "Check Now…" button. Check Now ignores the daily limit and the skipped version and always answers: the update alert (R48), "Deixis 0.6.0 is up to date." or "Deixis could not reach GitHub." as a standard alert.

**R48 The alert.** A standard `NSAlert`, once per newer version, never while the overlay is open (the check waits for `phase == .idle`). Message: "Deixis 0.7.0 is available". Informative: "You have 0.6.0. Download the dmg and drag Deixis over the copy in Applications; the permissions carry over because every release is signed with the same Developer ID." Buttons: "Download" (opens the release's dmg asset, or the release page when there is no asset), "Later" (asks again tomorrow), "Skip This Version" (sets `skippedUpdateVersion`; the next version asks again).

**R49 Sentences.** Site: "No telemetry, no accounts. The one request Deixis makes is a daily check for a newer version on GitHub; turn it off in Settings." README Install: the same, in place of "no network". README Git facts: "never talks to the network for this". `CLAUDE.md`: "No network calls except the release check (specs/v0.6.md R45)." Help, under Afterwards: "Updates", "Once a day Deixis asks GitHub whether a newer version exists and tells you. Turn it off in Settings." The two permission sentences are unchanged.

**R50 Release.** `scripts/release.sh` is unchanged: it builds, signs, notarizes, staples `build/release/Deixis-<version>.dmg`. `scripts/publish.sh` tags nothing; it requires the tag to exist, creates the GitHub release for it, and uploads the dmg as `Deixis.dmg` so `releases/latest/download/Deixis.dmg` is a stable URL for the site. `scripts/downloads.sh` prints the download count of every release asset through the GitHub API. Every Download link on the site points at `https://github.com/Malik1942/deixis/releases/latest/download/Deixis.dmg`.

**R51 Settings tabs (added Sep 14, after the tag, at Malik's request).** General held every row. Four tabs now, in System Settings' manner: General (the two permissions, the floating ball, Updates, Deixis Help), Hotkeys (the capture hotkey, the five action hotkeys and their clashes), Captures (folder, organization, retention, the selection handles, Color format and space), My Apps (unchanged). No row changes its wording; "Settings › General" in Help, README, and the code still points at what it did.
