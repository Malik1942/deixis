# Deixis v0.2: match the product, not the other way around

**Scope of this spec:** two slots that make the payload useful on apps that expose nothing, then the MCP server. Tagged `v0.2` when the server ships; `v0.2-region` after slot 2.
**Revision:** Sep 13, 2026, after v0.1 hands-on. Demo app is Oryne; the orb screen is the hard case.
**Out of scope:** floating ball, Color, Cut, lifecycle, Settings, Sparkle, Safari/Chrome URL (still deferred).

Read `CLAUDE.md` first, then `specs/v0.1.md` for everything this builds on. This file is the task contract.

## 1. Why this order

v0.1 found the ceiling: a code reference needs the app to have named something. Standard SwiftUI, AppKit and UIKit controls are named by default; SpriteKit, Canvas, Metal and weak Electron trees are not, and no tool can invent a name from pixels. Deixis therefore falls back through layers that need nothing from the app and says which layer produced the reference:

1. accessibility element (v0.1) → 2. cluster (v0.1) → 3. **a frame the user draws, with every element inside it** (slot 1) → 4. **text near the point, by OCR, and the nearest labeled neighbors** (slot 2) → 5. the image and the note (v0.1).

The MCP server (slot 3) is written once, against the schema after slots 1 and 2, so it lists region elements and text from day one.

## 4. Data model (schema v1, additive)

- `elements` (optional, array of `regionElement`): every element at least 50 percent inside the drawn frame, reading order, at most 12. `regionElement` is `{ role, rawRole, label, identifier, identifierSource, frame }`.
- `nearby` (optional, array of `regionElement`): for a null element, the 3 nearest labeled or identified elements around the click point.
- `ocr` (existing, string or null): recognized text lines joined by newlines, filled when the payload is vague: `element` null or without identifier, and no region element with an identifier.
- `element` for a region capture is the primary: the element nearest the frame's center that has an identifier, else one with a label, else null. `image.crop` is the drawn frame.

## 5. Payload additions

After the target element block, in both modes:

```
### Elements in frame (4)
staticText "Shortcut" · x=95 y=590 w=140 h=28
button "Action Button" · id=shortcutActionButton · x=59 y=660 w=169 h=50
…

### Nearby
button "Resurfacing, Catching a thought that drifted away" · 96 pt above
group "Tab Bar" · 520 pt below

### Text in image
Product Ideas
```

The source line reads `Image region: 402×160 pt @2x (drawn frame)` for region captures.

## 6. Requirements

**R11 Region gesture.** Press and drag on the overlay beyond 6 pt draws a marquee with `highlight.stroke`; a hud label at the corner reads `w × h pt`. Release confirms. A press without drag remains a point capture. Esc cancels at any time.

**R12 Elements inside.** On release, walk the tree of the app under the drag start (window hit-test as in R3), descending only through nodes whose frame intersects the frame, budget 800 nodes. Keep non-container elements at least 50 percent inside, drop duplicates with the same role and frame, sort in reading order, cap 12. If the walk returns nothing, retry twice at 100 ms (lazy tree). Each kept element is shown with a 1 pt `highlight.fallback` mark while the note field is open.

**R13 Crop.** The drawn frame exactly, clamped to the display. No padding.

**R14 OCR.** `VNRecognizeTextRequest`, `.accurate`, `en-US` and `zh-Hans`, on the crop, only when the payload is vague (section 4). Lines are ordered top to bottom, then left to right. Runs after the note is committed, before writing; adds at most a few hundred milliseconds.

**R15 Nearby.** For a null element from a point capture, the 3 nearest framed elements with a label or identifier among the spanning container's children, each with a plain offset: `96 pt above`, `40 pt left`, `inside`.

**R16 Honesty.** The payload always says which layer produced the reference: an element line, a cluster line, an elements-in-frame block, or the null block followed by nearby and text. Nothing is fabricated: OCR text is labeled as text in the image.
