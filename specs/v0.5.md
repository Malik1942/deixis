# Deixis v0.5: the first minute

**Scope of this spec:** What a new user meets between the dmg and the first paste, and the two gestures that must never miss: the click that picks, and the key that can stand in for it. Three hints that appear once and go away on their own, Return as a click everywhere the overlay is open, Esc checked on every surface, and two friction bugs in the click path. Tagged `v0.5`.
**Revision:** Sep 14, 2026, after `v0.4`.
**Out of scope:** A welcome window, a tour, a checklist, a Help window, tips that wait to be dismissed, any change to the ring's segments or to the note field, automatic relaunch after the Screen Recording grant (macOS asks for it itself).

Read `CLAUDE.md`, then the earlier specs. PRD §6.5 forbids onboarding tours and "any element that waits for the user"; this spec keeps to that. Every hint here is a toast: it appears, it says one line, it fades. Nothing is modal after the two permission alerts, and nothing is added to the overlay's chrome for good. PRD §6.3 says "no instructions anywhere on the overlay"; R39 relaxes that for the first three opens of each mode, the way R35 relaxed "no gallery". Decided by Malik (Sep 14).

## 1. What first launch looks like today, and what is wrong with the click

| Moment | Today | Gap |
|---|---|---|
| Launch | Two alerts, one per permission, then the ball fades in at the lower right | Nothing says what to press. The menu bar title "Capture (⌃⌃ or ⌃⌥1)" is the only hint in the app. |
| Screen Recording grant | The alert says why; the README says a relaunch is needed | The app does not say it. macOS shows its own Quit & Reopen alert when the switch is flipped for a running app, so the sentence only has to prepare the user for it. |
| First overlay | Highlight and `role · identifier` label | Drag, Option, and Esc are undiscoverable. |
| First Color | Magnifier and value | Arrow nudge is undiscoverable. |
| Click on the overlay, second display | The first click makes that screen's panel key and is dropped; the second click picks | `OverlayContentView` never answered `acceptsFirstMouse`. `BallView` did, with the comment "without this the first click only activates it". Only `panels.first` is made key, so every other display drops the first click. The Color catchers are the same class and have the same fault. |
| Slow click on the ball | A press longer than 300 ms opens the ring; releasing in place cancels; nothing happens | 300 ms is under a hesitant click. AppKit's own `NSPressGestureRecognizer.minimumPressDuration` is 0.5 s. |
| Keyboard | Return confirms a drawn frame and commits the note; nothing else | The hover is the selection. Return should take it, in every mode, so a capture never depends on a precise click. |

## 4. Requirements

**R37 First click counts.** `OverlayContentView.acceptsFirstMouse` returns true, as `BallView` already does. A click on any display's panel is a click, whether or not that panel is key. Applies to the Color catchers, which are the same view.

**R38 Return is a click.** With the overlay open and nothing locked, Return or keypad Enter acts as a click at the current cursor position (`NSEvent.mouseLocation`, converted the same way a mouse-up is): Point takes the hovered element at its Option level and opens the note field; Snap and Cut take the window under the cursor; Text takes the hovered element; Color copies the magnified pixel. The existing Return behaviors stay: a drawn frame with handles is captured, a note is committed. Esc cancels in every one of these states (audited: overlay hover, region adjust, note field, Color; the ring cancels by release at center and needs no key).

**R39 Ring hold.** `Ring.Tokens.holdDelay` becomes 0.5 s, AppKit's press default. A press released before that is a click and starts Point. Labels still fade in 200 ms after the ring opens.

**R40 Hints.** A hint is a toast on `label.bg`, `label.sans`, shown once per key and then never again; `Preferences.hintCounts` keeps a count per key (UserDefaults, a dictionary). No hint has a close control, a Next, or a Don't show again; it lives `hint.life` (6 s, long enough to read one line) and fades with `motion.dismiss`. A click, a drag, or Esc hides it early.

- `launch`: once, after the permission alerts, anchored below the ball (or at the center of the main screen when the ball is off): `Point at anything: ⌃⌃, or click the ball` with the current capture hotkey's symbol; without the ball, `Point at anything: ⌃⌃, also in the menu bar`.
- `overlay.point`, `overlay.snap`, `overlay.text`, `overlay.cut`, `color`: shown at the bottom center of the display that holds the cursor (the ⌘⇧5 toolbar's spot, so it never sits over the hover label) on each of the first three opens of that mode, then never. Text, by mode:
  - Point: `Click or ↩ picks the element · drag for a frame · ⌥ for the parent · esc cancels`
  - Snap and Cut: `Click or ↩ takes the window · drag for a frame · ⌥ for clipboard only · esc cancels`
  - Text: `Click or ↩ takes the element · drag for a frame · esc cancels`

  Every line fits `HudLabel`'s 480 pt text cap at `label.sans`; a longer one is truncated, so wording is trimmed rather than the cap raised.
  - Color: `Click or ↩ copies · arrows nudge a pixel · esc cancels`

Three showings rather than one because the first open is usually spent looking at the highlight; the store counts, the caller caps at three.

**R41 Permission sentence.** The Screen Recording alert reads: `Deixis captures the element through Screen Recording. Nothing leaves the machine. macOS applies this grant after Deixis reopens; it will offer to do that.` The Accessibility sentence is unchanged.

**R42 README.** The Use section leads with the hotkey and adds Return; Install says what the hints are and that they stop by themselves. Version 0.5.0.

## 5. Tests

`RingTests`: `holdDelay == 0.5`.
No UI tests; slot 1's exit condition is checked by hand with synthetic input on the second display.
