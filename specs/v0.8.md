# v0.8: web nodes carry the DOM's handles; Shift selects more than one element

**Status:** R57 built Sep 16, 2026. R58 in progress.

## R57 DOM identifiers for browsers and Electron

WebKit and Chromium publish three attributes on web nodes that nothing else has: `AXDOMIdentifier`,
`AXDOMClassList`, and `AXURL` on the web area. Verified on this Mac in Dia (Chromium) and the Claude
desktop app (Electron) on Sep 16, 2026. Safari publishes the same and is untested.

- `AttributeSet` gains `domId` and `domClasses` (fixture keys `AXDOMIdentifier`, `AXDOMClassList`).
  `domClasses` is non-nil, possibly empty, exactly when the node is a web node.
- The reader reads both on the hit element always (a nil answer is one cheap failed read on native
  apps) and on the ancestors only when the element is a web node. The page URL is read from the
  nearest `AXWebArea` above the element, climbing past the six ancestors a snapshot keeps, cached
  per app for 400 ms. It lands in `ElementSnapshot.url`.
- `ResolvedElement.dom` (`{ id, classes }`) is present for web nodes. `identifier` stays the
  accessibility identifier. A path entry without an identifier carries `dom`: `#id`, else `.firstClass`.
- Markdown: `button "Checkout" · #checkout-button · .btn.btn-primary`; classes capped at six with
  `(+n more)`; path segments read `group#checkout > group.actions`. The advice line for a web node
  says to give the element an id, not `.accessibilityIdentifier`. `URL:` prints under the source.
- Hover label: a web node without an accessibility identifier shows `#id`, else its first two classes.
- The click path copies the snapshot's URL into `source.url`, so the localhost rule in mode inference
  wakes: a page on `localhost`, `127.0.0.1`, `0.0.0.0`, `::1`, or `*.local` is fix mode.
- Schema: `element.dom`, `pathEntry.dom`, and the `source.url` description. Region elements and
  nearby elements do not carry DOM handles in this version.
- Tests: `DOMIdentifierTests` over `chromium-button.json` and `chromium-classes-only.json`.

## R58 Shift selects more than one element

Point's trigger is unchanged. With Shift held, a click adds the hovered element to the selection
instead of ending it, the way Finder and Figma select more than one thing; a plain click on the
last element, or Return, opens the note field for the whole set. Option still steps to the parent
and a drag still draws a frame. Elements may come from different apps: the second can be the
reference in Safari or Figma while the first is the view in the Simulator.

- Overlay: every selected element keeps its outline and a number; the hovered one keeps the label.
  Shift-clicking a selected element removes it. The note field opens under the last element.
- Payload: `### Element 1 (this)`, `### Element 2 (that)`, then `### Element 3` and so on, each with
  its own app and window line when it differs from the source. The sidecar's `element` stays the
  first target so iterations and the MCP tools keep working; `targets` holds the ordered set.
- Image: one crop of the union of the frames plus the usual margin when it fits on one display and
  covers less than 60 percent of it; otherwise one crop per element, `Image 2:` on its own line.
- Teaching: a row on the help page, a line on the site, and a one-time hint the first time Shift
  is held on the overlay: `⇧ click adds another element`.
