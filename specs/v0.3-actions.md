# Locant v0.3-actions: the one-shot actions and the ring

**Scope of this spec:** PRD §6.3's action set, organized by what you are about to paste: Snap, Text, Color, Cut, the ring on the ball, per-action hotkeys, pin, and the 30-day lifecycle. Tagged `v0.3-actions`. Verify (v0.4) and the MCP server stay after it.
**Revision:** Sep 13, 2026, after `v0.3`.
**Out of scope:** URL scheme and Raycast (deferred), nearest-Tailwind color name, flood-fill fallback for Cut, Sparkle.

Read `CLAUDE.md`, then `specs/v0.1.md`, `v0.2.md`, `v0.3.md`. Visuals from `docs/PRD.md` §6; the surface specs for the ring, magnifier, and cut picker are there. Point stays the primary action: click on the ball is Point, the ring is press-and-hold only, and nothing in this spec changes the Point flow.

## 1. The rule that decides file behavior

Actions that produce an image keep a file for the retention period; actions that produce text or a value keep nothing.

| Action | You paste | Trigger | Clipboard | Disk |
|---|---|---|---|---|
| Point | element + crop + note | hotkey, ball click | yes | yes, retained; resolved or pinned captures are kept |
| Snap | an image | ring ↑, hotkey | yes | yes, retained. ⌥ held at release: clipboard only |
| Text | recognized text | ring →, hotkey | yes | no |
| Color | a color value | ring ↓, hotkey | yes | no |
| Cut | an image with transparent background | ring ←, hotkey | yes | yes, retained. ⌥: clipboard only |

## 4. Requirements

**R22 Modes.** The overlay opens in a mode. Point is unchanged. Snap, Text, and Cut show the marquee gesture; Snap and Cut also accept a click, which takes the window under the cursor (window hit-test as R3). Text takes a click as the element under the cursor, expanded by 8 pt. Esc cancels. No note field for one-shot actions.

**R23 Snap.** The region or window pixels through `ScreenCapture.crop` (own windows excluded). Clipboard gets the PNG; disk gets `locant-snap-<slug>-<id>.png`, no sidecar. ⌥ held on release skips the file. Toast: `Snapped · 640×480`.

**R24 Text.** `TextRecognizer` on the crop; language correction on. Clipboard gets the lines joined by newlines. Nothing on disk. Toast: `Copied · n lines`, or `No text found` (failure style, clipboard untouched).

**R25 Color.** A magnifier panel (PRD §6.3 "Color magnifier") follows the cursor with no smoothing: 15×15 native pixels at 10x from a fresh 15×15 px screen read each move (own windows excluded; the magnifier itself is a Locant window, so it never samples itself). The center pixel is outlined with `highlight.stroke`; the current value in `label.mono` beneath. Arrow keys nudge by one pixel. Click copies in the selected format; Esc cancels. Formats: `#RRGGBB`, `rgb(r, g, b)`, `hsl(h, s%, l%)`, `Color(red:green:blue:)` for SwiftUI. Color space sRGB by default, Display P3 by Settings. Last format remembered (`colorFormat` key). Last 10 colors kept in memory only.

**R26 Cut.** `VNGenerateForegroundInstanceMaskRequest` on the crop; the instance under the click point (or all instances for a region) is composited onto transparency; PNG with alpha to clipboard and disk (`locant-cut-<slug>-<id>.png`). ⌥ skips the file. When Vision finds no subject: failure toast, nothing written.

**R27 Ring.** Press and hold the ball for 300 ms: four segments unfold from the disc (Snap ↑, Text →, Color ↓, Cut ←), `label.bg`, outline SF Symbols (`camera.viewfinder`, `text.viewfinder`, `eyedropper`, `person.and.background.dotted`), the filled pointing hand at center. One-word labels fade in 200 ms after the ring opens. ⌥ appends a small ⌥ to Snap and Cut. Release over a segment starts that action; release at center cancels. Hover-to-expand does not exist. A plain click remains Point; a drag remains a move. The ring closes with `motion.dismiss`.

**R28 Lifecycle.** Setting `retentionDays` (7 / 30 / 90 / 0 = never, default 30). On launch and every 24 h, image files under the capture folder (recursively) older than retention move to the Trash with their sidecars, unless the sidecar has `resolved: true` or the file carries the `app.locant.pinned` extended attribute. "Pin last capture" in the menu bar sets the attribute on the newest capture's files. Pure sweep function over a listing, tested.

**R29 Hotkeys per action.** Settings General gains recorders for Point, Snap, Text, Color, Cut. Defaults (decided Sep 13, 2026, superseding "unassigned"): ⌃⌥ and the action's digit in menu order, ⌃⌥1 to ⌃⌥5; the family types nothing on any layout and no known app or macOS shortcut sits on it. The menu bar and the ring show each digit. Clearing an action is remembered; only departures from the defaults are stored. One session event tap serves every hotkey and swallows a matched chord so it never also reaches the frontmost app (double-taps pass through); without Accessibility trust, `NSEvent` monitors observe instead. The recorder refuses a hotkey another Locant action holds and warns, without blocking, when a chord is an enabled macOS shortcut (read from `CopySymbolicHotKeys`). Menu bar: Capture, Snap, Text, Color, Cut, Pin last capture, Open capture folder, Settings…, Quit.

**R30 Honesty and safety.** Every action's toast says what was produced. Failures leave the clipboard untouched. Locant's own windows (overlay, magnifier, ring, ball, toasts) never appear in any image.

## 5. Tests

`ColorPickerTests`: hex, rgb, hsl, SwiftUI formatting of known values; P3 vs sRGB differ for a saturated color; grey is identical in both.
`LifecycleTests`: a listing with a 40-day-old capture, a 10-day-old one, a 40-day-old pinned one, and a 40-day-old resolved one → only the first is swept; retention 0 sweeps nothing.
Existing suites keep passing; no UI tests.
