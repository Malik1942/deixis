# Deixis v0.4: see what changed

**Scope of this spec:** Verify with a manual trigger. After a fix-mode capture and an agent's edit, "Capture after" finds the same element in the running app by its identifier, captures it again, records the git facts, and shows before and after side by side. Tagged `v0.4`. Automatic rebuild triggers are an enhancement after this path is proven (PRD P2.1's open spike), not part of it.
**Revision:** Sep 13, 2026, after `v0.3-actions`.
**Out of scope:** Xcode / git-hook / Claude Code Stop triggers, pixel-diff judgments, a timeline or gallery, the MCP server.

Read `CLAUDE.md`, then the earlier specs. PRD §7.4 is the source; §6.3 "Before/after panel" the look.

## 1. What a verify needs, and where it comes from

| Need | Source |
|---|---|
| Which capture | the newest Point capture in the folder (recursively), or the one open in the panel |
| Which app | `source.app.bundleId`, or the Simulator for Simulator captures; found among running apps |
| Which element | `element.identifier` first; else role plus label; else role plus nearest frame to the original (PRD P2.2) |
| Before image | the capture's own PNG |
| After image | a fresh crop of the found element, same padding as R4, `deixis-<slug>-<id>-after-<n>.png` beside the original |
| Git before | `source.gitCommit`, recorded at capture time when a project root is known (new, additive) |
| Git after | `HEAD` at verify time; when it equals before, the working tree diff is used, since agents often edit without committing |
| Diff stat and files | `git diff --stat` and `git diff --name-only` between the two, or against HEAD for the working tree |

## 4. Data model (schema v1, additive)

- `source.gitCommit` (optional string): the project's HEAD when the capture was made. Absent without a project root or outside a repository.
- `iterations[]` entries as the PRD defines them: `capturedAt`, `imagePath`, `gitBefore`, `gitAfter`, `diffStat`, `files`, plus an optional `frame` (where the element was found, screen points).

## 5. Requirements

**R31 Refind.** Locate the app by bundle id among running apps (the Simulator itself for Simulator captures). Walk its tree the way region select does, over the app's largest window. Match in order: identifier equal; role and label equal; role equal and frame center nearest the original within 200 pt. Retry every 500 ms for up to 5 s. Failure: toast `Element not found · <identifier or label>`, nothing written.

**R32 After image.** The found element's frame plus R4 padding, clamped to its window, through `ScreenCapture.crop` (own windows excluded). Written beside the original as `deixis-<slug>-<id>-after-<n>.png`, Finder tags as the original plus `after`.

**R33 Git facts.** Only when `source.projectRoot` exists and is inside a repository. `gitBefore` from the sidecar; `gitAfter` is HEAD now. Diff between them, or the working tree against HEAD when they are equal. Never a hook, never a commit, never a network call. Missing git or a non-repository yields nulls, not errors.

**R34 Iteration record.** Appended to the capture's sidecar; the sidecar is rewritten whole (last writer wins, the app never caches sidecars). `resolved` is untouched.

**R35 Panel.** A standard window titled "Before & After": the note above, before and after images side by side sharing one zoom slider, an iteration picker when there are several, the diff stat and file list beneath in `label.mono`. No judgment, no pixel diff, no timeline. Reachable from the menu bar ("Show before & after", the newest capture with iterations) and opened after a successful Capture after.

**R36 Menu bar.** Adds "Capture after" and "Show before & after" between Point's items and the one-shot actions.

## 6. Tests

`ElementRefinderTests`: identifier wins over a same-label sibling; role and label match when the identifier is absent; nearest frame within 200 pt as the last resort; nothing beyond 200 pt.
`IterationStoreTests`: append to a sidecar on disk round-trips through `Capture`, keeps earlier iterations and `resolved`; after-image name increments.
`GitFactsTests`: `diff --stat` summary parsing ("3 files changed, 12 insertions(+), 4 deletions(-)") and name-only splitting.
