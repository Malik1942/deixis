# Deixis v0.1: the pointing flow

**Scope of this spec:** the 3-hour version, tagged `v0.1`. One hotkey, one click, one payload.
**Revision:** Sep 13, 2026, after the AX spike. Demo app is Oryne.
**Out of scope (v0.2+):** MCP server, drag selection, floating ball, OCR, color picker, cutout, 30-day lifecycle, Settings UI, Sparkle, Safari/Chrome tab URL (deferred to v0.2; `url` stays null).

Read `CLAUDE.md` first. This file is the task contract.

---

## 0. What changed since the PRD

Competitive research (Sep 12, 2026) moved three things:

1. **Window-level context is already a platform feature.** Codex Appshots (Command-Command) sends the front window's screenshot plus accessibility text to a Codex thread. Claude Desktop quick entry (Option-Option) attaches a region or window to a Claude chat. EYHN/appshots clones this for Claude Code. So v0.1 does **not** do window capture. It does element capture only. Pitch line: "Appshots gives your agent the window. Deixis gives it the element."
2. **MCP image content blocks are unreliable across agents.** Claude Code and Cursor consume them. Codex has two open issues (model cannot see the image; `content[]` dropped when `structuredContent` is present). Gemini CLI unconfirmed. Therefore the payload's primary form is **text plus an absolute image path**, and v0.1 writes a JSON sidecar so the v0.2 MCP server needs no app changes.
3. **The element schema must be platform-neutral.** Windows UI Automation and macOS Accessibility expose the same concepts (role, name, identifier, frame, ancestry). Field names use no `AX` prefix so a future Windows port shares the schema and the MCP server unchanged.

4. **The AX spike passed (Sep 13).** Per-app hit testing reaches the Simulator's app tree through public API; frames are in screen points; the tree is built lazily; SF Symbol names show up as identifiers. R3, the schema, and the tests reflect all four findings.

Double-tap modifier keys are now the convention for "send context to agent" (Codex: ⌘⌘, Claude: ⌥⌥). Deixis defaults to **double-tap Control** to avoid both.

## 1. Goal

Press the hotkey, click one element in any app, optionally type a note, press Enter. The clipboard now holds a Markdown payload (and the PNG) that lets a coding agent find the right file. Demo target: the primary capture button in the Oryne iOS Simulator with `.accessibilityIdentifier("captureButton")` (added Sep 13), pasted into Claude Code, agent edits the correct view on the first try.

## 4. Data model (`schema/capture.schema.json`, v1)

```json
{
  "schemaVersion": 1,
  "id": "20260912-140312-k7q2",
  "createdAt": "2026-09-12T14:03:12-07:00",
  "mode": "fix",
  "image": {
    "path": "/Users/malik/Pictures/Deixis/deixis-simulator-20260912-140312-k7q2.png",
    "widthPt": 144, "heightPt": 112, "scale": 2,
    "crop": { "x": 272, "y": 48, "w": 144, "h": 112 }
  },
  "source": {
    "app": { "bundleId": "com.apple.iphonesimulator", "name": "Simulator" },
    "window": { "title": "iPhone 17 Pro" },
    "url": null,
    "simulator": { "device": "iPhone 17 Pro", "appBundleId": "com.malikzhang.oryne" }
  },
  "element": {
    "role": "button",
    "rawRole": "AXButton",
    "label": "Capture",
    "identifier": "captureButton",
    "identifierSource": "declared",
    "value": null,
    "frame": { "x": 312, "y": 88, "w": 64, "h": 32 },
    "path": [
      { "role": "group", "identifier": null },
      { "role": "toolbar", "identifier": null },
      { "role": "button", "identifier": "captureButton" }
    ]
  },
  "note": "make this rounded, match the other toolbar buttons",
  "ocr": null,
  "iterations": [],
  "resolved": false
}
```

Rules:
- `element` is `null` when resolution fails. Never fabricate.
- `role` values are lowercase, platform-neutral (`button`, `textField`, `staticText`, `image`, `group`, `navigationBar`, `unknown`). `ElementResolver` maps `AXButton` → `button` etc. Unknown AX roles map to `unknown`. `rawRole` always carries the platform's own role string.
- `id` is `yyyyMMdd-HHmmss-xxxx`: local stamp plus 4 random base36 characters, so two captures in one second never collide. "Latest" means newest `createdAt`, ties broken by `id`.
- `image.crop` is the crop rectangle in global screen points, so an agent can place `element.frame` inside the image.
- `ocr` and `iterations` are always `null` and `[]` in v0.1. They exist so the v0.2 MCP server and v0.4 Verify can add data without an app change.
- `path` is the nearest 6 ancestors, root-first, followed by the element itself (max 7 entries).
- `identifierSource` is `possiblySymbolName` when role is `image` and the identifier matches `^[a-z0-9]+(\.[a-z0-9]+)*$` (SF Symbol naming); `declared` for any other non-empty identifier; `unknown` when empty. (Observed: an SF Symbol image reported `AXIdentifier = plus`; agents must not grep for that as if a developer declared it.)
- `mode` is `fix` when: the front app's bundle id is in `MyApps` (hard-coded array in v0.1); or the front app is Simulator and the simulated app's bundle id is in `MyApps` or could not be read; or URL host is localhost/127.0.0.1. Else `reference`. Simulator running someone else's app is `reference`.
- `url` is always null in v0.1. The Safari/Chrome read (AppleScript, Automation prompt, usage string) is deferred to v0.2. The localhost rule stays implemented for when it arrives.

## 5. Payload (Markdown on clipboard)

Fix mode:

```
## Deixis capture (fix)
Image: /Users/malik/Pictures/Deixis/deixis-simulator-20260912-140312-k7q2.png
App: Simulator (com.malikzhang.oryne) · Window: iPhone 17 Pro
Captured: 2026-09-12 14:03 · Image region: 144×112 pt @2x (element + 40 pt)

### Target element
button "Capture" · id=captureButton
Frame: x=312 y=88 w=64 h=32
Path: group > toolbar > button#captureButton

### Note
make this rounded, match the other toolbar buttons
```

Reference mode leads with `### Note`, then source, then element if any.

When `identifierSource` is `possiblySymbolName`, the element line carries a caveat:

```
image · id=plus (may be a symbol name, not a declared identifier)
```

When `identifier` is null, the element line ends with `· no identifier` and a hint line follows, so the missing id is fixed in the same loop:

```
button "Capture" · no identifier
No identifier. Grep the label text; add .accessibilityIdentifier("…") to this view so the next capture is exact.
```

When `element` is null:

```
### Target element
No element information available (app exposes no accessibility tree). Use the image.
```

The `Image:` line is first because terminal agents (Claude Code, Codex CLI) receive only the text representation on paste; they read the PNG from disk. Claude Code accepts the path directly; Codex uses `view_image`.

## 6. Requirements

**R1 Hotkey.** Double-tap Control within 350 ms opens the overlay. Implemented with `NSEvent.addGlobalMonitorForEvents(matching: .flagsChanged)`. Requires no permission beyond Accessibility (already needed).

**R0 Visuals.** All colors, type, spacing, and motion come from `docs/PRD.md` section 6 (Design language), tokens table and surface specs for Overlay, Note field, Toast, No-element, Menu bar, Permissions. Do not invent values; if a token is missing, ask.

**R2 Overlay.** One borderless, transparent, non-activating `NSPanel` per screen, `level = .screenSaver`, `canBecomeKey = true`, over the live screen under `dim`. No frozen frame: pixels and tree cannot disagree, and the front app keeps focus so menus stay open and paste lands where it should. Hovering highlights the AX element under the cursor (frame from `ElementResolver`, throttled to 30 Hz) with `highlight.stroke`, and the `label.bg` label beside it reads identifier quality before the click: `button · captureButton` (identifier in `label.mono`), `button "Capture" · no identifier` (suffix in `secondaryLabelColor`), `image · plus · may be a symbol name`, or the no-element state `no element info · image only` with `highlight.fallback`. Click confirms. Esc cancels with no side effects.

**R3 Element resolution.**
- Primary path: on hover and on click, find the topmost normal-layer window under the point via `CGWindowListCopyWindowInfo`, excluding Deixis's own windows, and take its owner PID; fall back to the frontmost PID recorded at hotkey time (R5). Call `AXUIElementCopyElementAtPosition` on `AXUIElementCreateApplication(pid)`. The per-app query ignores any window layered above the target, including Deixis's own overlay, so the overlay never needs to hide for resolution. Every visible window is an honest target rather than a null hit.
- Fallback: the system-wide element (`AXUIElementCreateSystemWide()`), only if the per-app query returns nil.
- Lazy-tree retry: if the hit returns nil, or a `group` with zero children, retry every 100 ms up to 5 times before recording `element: null`. (Observed Sep 13: the Simulator's app tree was empty on first read and had 45 nodes seconds later; iOS builds it on first client access.)
- Read `AXRole`, `AXSubrole`, `AXTitle`, `AXDescription`, `AXValue`, `AXIdentifier`, `AXFrame`. Frames come back in global screen points; no conversion needed. Walk `AXParent` up to 6 times. Map to `ResolvedElement`, including `identifierSource` (section 4). All AX calls run on a background actor; overlay stays responsive.

**R4 Crop.** At click time, capture the element's frame plus 40 pt padding on each side with `SCScreenshotManager.captureImage` and `SCContentFilter(display:excludingWindows:)` excluding Deixis's own windows, clamped to the target window's bounds and then to the display. The padding shows neighbors, since the job is layout polish. When `element` is null, the crop is a 120 pt square around the click point plus the same padding. The crop rectangle is recorded in `image.crop`. This is the PNG. (Full-window capture is deliberately not offered; Appshots does that.)

**R5 Context.** Collected at hotkey time, before the overlay appears, as the fallback. On click, when the clicked window belongs to a different app than the one that was frontmost, the source is re-collected for that app, so `source`, `mode`, and the window title describe what was pointed at (observed Sep 13: Finder frontmost, Simulator clicked, payload said Finder/reference). Simulator app bundle id comes from the most recently started process under `CoreSimulator/Devices/…/Containers/Bundle/Application`; null when none. No URL read in v0.1.

**R6 Note.** After click, a single-line `NSTextField` appears anchored below the element's frame, styled per the PRD note-field spec. Enter commits; empty note allowed. Esc cancels the whole capture: nothing on disk, clipboard untouched. Only Enter writes. The hint therefore reads `↩ copy · esc cancel` (the PRD's `esc skip` predates this rule).

**R7 Write.** `FileStore` writes PNG and JSON to `~/Pictures/Deixis/` (created if missing), as `deixis-<slug>-<id>.png` and `.json`. Filename slug is the app name lowercased, non-alphanumerics removed, max 16 chars.

**R8 Clipboard.** One `NSPasteboardItem` with `.png` and `.string` (Markdown). Never overwrite the clipboard on failure.

**R9 Failure feedback.** `CaptureError` cases: `.noAccessibilityPermission`, `.noScreenRecordingPermission`, `.noElementUnderCursor`, `.captureFailed(Error)`. Permission errors open the relevant System Settings pane once. `.noElementUnderCursor` still produces a capture with `element: null` (R5 text). `.captureFailed` shows a 1-second toast and leaves clipboard and disk untouched.

**R10 Menu bar.** Status item with the app name, "Capture (⌃⌃)", "Open capture folder", "Quit". Nothing else.

## 7. Tests (must pass before tag)

`ElementResolverTests` (fixtures recorded from the spike, stored as JSON dictionaries of AX attributes):
1. SwiftUI button with identifier → `role=button`, `identifier=captureButton`
2. AppKit text field without identifier → `role=textField`, `identifier=nil`, label from `AXTitle`
3. Unknown role `AXCustomThing` → `role=unknown`, `rawRole` preserved
4. Path truncates at 6 ancestors, root-first order
5. Missing `AXFrame` → resolver returns nil, not a zero frame
6. Simulator element path includes the simulator's own window group and still resolves the app's identifier
7. Empty first read followed by a populated read → resolver returns the populated element (stubbed provider exercises the retry path)
8. `image` with identifier `plus` → `identifierSource = possiblySymbolName`; `button` with `captureButton` → `declared`

`MarkdownBuilderTests`:
1. Fix mode ordering (image line first, element before note)
2. Reference mode ordering (note first)
3. Null element renders the "No element information" block
4. Empty note omits the `### Note` section entirely
5. Identifier with `#` and quotes is not escaped into something un-greppable
6. `possiblySymbolName` renders the caveat; `declared` does not
7. Null identifier renders `· no identifier` and the hint line

`GeometryTests`:
1. AppKit → CG point flip round-trips on the primary display
2. CG rect → AppKit rect flip
3. Crop = element + 40 pt, clamped to the window, then to the display
4. Pixel rect on a secondary display with negative origin and scale 2
5. Window hit-test picks the topmost layer-0 window under the point and skips Deixis's own

`FileStoreTests`:
1. Slug: lowercase, non-alphanumerics removed, max 16
2. Id matches `yyyyMMdd-HHmmss-xxxx`

## 10. Decisions deferred to v0.2

- Build the MCP server (TypeScript, `npx deixis-mcp`) reading the JSON sidecars. Tools: `list_captures`, `get_capture(id, include_image=false)`, `resolve_capture(id)`. Return text plus path by default; image block only when `include_image` is true; never combine `structuredContent` with an image block (Codex bug).
- Evaluate reusing Peekaboo's `see` for AX parsing versus keeping `ElementResolver`. Default: keep our own; it is 100 lines and testable.
- Drag selection with multi-element resolution.
- Hotkey and folder in Settings.
