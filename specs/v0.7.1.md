# Locant v0.7.1: the agent fetches it

**Scope of this spec:** the MCP server from `specs/v0.2.md` slot 3, and a way to connect it to Claude Code, Cursor, and Codex from Settings. Tagged `v0.7.1`.
**Revision:** Sep 14, 2026, after `v0.7`. Malik's order: Claude Code first, then Cursor, then Codex.
**Out of scope:** an npm package (nobody is logged in to npm, and a second install step for a tool that is already on the Mac is one too many), HTTP transport, a watcher or push notifications, resources and prompts, a Raycast or URL-scheme trigger, Gemini and Antigravity.

Read `CLAUDE.md`, then the earlier specs. PRD §7.2 asked for a TypeScript package started with `npx locant-mcp`. This spec puts the server inside the app instead: the same binary, started with `--mcp`, speaking MCP over stdio. The tools, the compatibility rules, and the config-per-agent promise of P1.2 to P1.4 are kept; the language and the install step are not. Reasons: the sidecars are on this Mac, so the server must be too; the app is already signed, notarized, and updated; nothing to publish, nothing to keep in step with the schema; no Node required.

## 4. Requirements

**R53 The server.** `Locant --mcp` runs an MCP server on standard input and output and nothing else: no `NSApplication`, no window, no permission prompt, no menu bar item, no defaults written. Messages are JSON-RPC 2.0, one per line, the MCP stdio transport. `initialize` answers with the client's protocol version when it is one of `2025-06-18`, `2025-03-26`, `2024-11-05`, else the newest; capabilities are `tools` only; `serverInfo` is `locant` and the bundle version; `instructions` tell the model what a capture is and to call `latest_capture` when the user says "what I just pointed at". `ping` answers `{}`. Notifications get no reply. An unknown method is `-32601`, a bad line `-32700`. The process exits when stdin closes. The capture folder is `Preferences.captureFolder` from the shared defaults, or `--folder <path>` when given; every sidecar under it, recursively, whose name starts with `locant-` or `deixis-` and decodes as a v1 capture, is a capture. Nothing is cached; every call reads the folder. Stdout carries only responses; anything else goes to stderr.

**R54 Tools.**
- `latest_capture(include_image?: false, unresolved_only?: false)`: the newest capture by `createdAt`, ties by id. What the user means by "this", "what I just pointed at".
- `list_captures(unresolved_only?: false, limit?: 20)`: one line per capture, newest first: id, when, mode, app, the element in the payload's words, the note, resolved or not.
- `get_capture(id, include_image?: false)`: the payload exactly as the clipboard would carry it (`MarkdownBuilder.build`), then a `### Sidecar` block with the JSON file's path and its text, so iterations and everything the Markdown omits are there.
- `resolve_capture(id)`: sets `resolved: true` in the sidecar and nothing else; the file keeps every other key. The retention sweep then keeps the capture (R28).
An unknown id is a tool result with `isError: true`, not a protocol error. An empty or missing folder says so and names the hotkey.

**R55 Compatibility (PRD P1.3).** Every tool result starts with text, and for a capture the text starts with the image path. An image content block (`image/png`, base64) is added only when `include_image` is true. No tool ever returns `structuredContent`. Read tools carry `readOnlyHint`; `resolve_capture` is `idempotentHint`.

**R56 Settings › Agents.** A fifth tab. One row per agent, in Malik's order: Claude Code, Cursor, Codex. Each row shows the agent's state, re-read every two seconds while the window is open: "Connected" with the green tick, "Not connected" with the orange mark, or "Connected to another copy" when the agent's config names a different Locant executable (a Debug build, a moved app). Trailing: Connect, Disconnect, or Reconnect. Connect writes one stdio server named `locant`, command `<this bundle>/Contents/MacOS/Locant`, args `["--mcp"]`, into the agent's own user-level configuration:
- Claude Code: `claude mcp add --scope user locant -- <exe> --mcp` when the `claude` CLI is found (`~/.local/bin`, `/opt/homebrew/bin`, `/usr/local/bin`, `~/.claude/local`); else `mcpServers.locant` in `~/.claude.json`. Disconnect is `claude mcp remove --scope user locant`, else the key removed.
- Cursor: `mcpServers.locant` in `~/.cursor/mcp.json`, other servers untouched.
- Codex: a `[mcp_servers.locant]` table appended to `~/.codex/config.toml`; Disconnect removes that table and its sub-tables. Not `codex mcp add`: it re-serializes the whole file (key order, `120` to `120.0`, indentation), and the file is the user's own.
The text merges are pure functions with tests; the CLI calls are not. A failure shows in the row as one sentence; nothing else. Under the rows, a footnote names the command that is written and the four tools. A second group, "Any other agent", copies the JSON snippet. Nothing runs until an agent starts the server.

**R57 Sentences.** README: an "Over MCP" section under Use, the three ways to connect (Settings › Agents, or the command line, or the snippet), and the agent table gains an MCP column with the date each row was run. Site: the "Works where you paste" rows say what was tested and when, and the lede names MCP. Help, under Afterwards: "Or let the agent fetch it", detail "Connect Claude Code, Cursor, or Codex in Settings › Agents. Say what should change; the agent pulls the capture itself, image included." `CLAUDE.md` Data contract: the server reads the sidecars through the same `Capture` model; the schema is still the only interface.

**R58 Release.** Version 0.7.1, tag `v0.7.1`, `scripts/release.sh`, `scripts/publish.sh`. The site footer says 0.7.1.

## 5. Tests

`MCPServerTests`: 1. initialize echoes a known protocol version and lists only tools; 2. tools/list names the four tools with their schemas; 3. list_captures over a folder with two sidecars is newest first and honors `unresolved_only`; 4. latest_capture text starts with the Markdown payload and the image path; 5. get_capture with `include_image` adds one image block and no `structuredContent`; 6. resolve_capture flips `resolved` and leaves every other key as written; 7. unknown id is `isError`; 8. unknown method is -32601, a notification gets nil, a bad line -32700; 9. an empty folder answers with a sentence, not an error.
`AgentConfigTests`: 1. JSON add keeps other servers and replaces an old `locant`; 2. JSON remove leaves the rest and returns nil for an empty file; 3. TOML add appends one table after existing ones; 4. TOML remove takes exactly that table, including its sub-tables; 5. detection returns the configured executable for each format.
